# 0001 — Non-deterministic Active Record Encryption for note bodies

We encrypt Note#body with Active Record Encryption in non-deterministic (probabilistic) mode rather than deterministic. Deterministic encryption would allow SQL-level querying (`LIKE`, `ORDER BY`, indexing) against encrypted data at the cost of weakened security (same plaintext → same ciphertext, enabling frequency analysis). For a personal note app, the decryption overhead of loading all notes on the index page is negligible, and there is no requirement for server-side full-text search. Non-deterministic encryption is the safer default: each encryption of the same plaintext produces different ciphertext, making it resistant to frequency-analysis attacks. If full-text search becomes necessary later, we can add a separate search index (e.g., FTS5 on SQLite) rather than weakening the encryption mode.
